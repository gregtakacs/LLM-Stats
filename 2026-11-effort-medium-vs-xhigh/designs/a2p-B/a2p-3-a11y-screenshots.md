# A2P step 3 — keyboard/ARIA audit, and the eight acceptance screenshots (full gate)

(derived from docs/specs/a2p-design.md §6, §7, §8; harness rules §7a/§10 — hard as the chain's
closing step; the owner asked for screenshots as acceptance evidence and named this the step that
produces them, and the last step of every chain runs the full gate.)

**This step is the acceptance gate for the whole slice.** Two deliverables: a keyboard/ARIA test
suite that proves the contract in design §6, and the browser test that produces the eight PNGs
(design §8) as *test output* — a verify that fails when they are missing, so nobody can report the
step green on "I think it looked fine". Steps 1–2 built the UI; this step proves it and its
accessibility, then runs everything.

## Goal

The picker is operable with the keyboard alone and announces itself correctly: Tab reaches every
control in DOM order, Enter/Space activate, the arrow keys move among the menu items, Escape closes
and returns focus, `aria-expanded` tracks the dropdown, disabled controls stay reachable and say
why. And the UI is shown, in both themes at both viewports, in the states the owner will review —
the screenshots are a required test artifact, generated by a deterministic test (explicit waits, no
sleeps), not a human ritual.

## Contract

### The a11y suite — `hub/tests/test_a2p_a11y.py`

Source-level (unittest, browser-free, in the `TestSessionPickerInSource` style):

1. **Native controls, DOM-order tab order**: every interactive control in the bar and dropdown is a
   real `<button>` or `<a>`; the shipped views contain no `tabIndex` assignment anywhere; the bar's
   DOM order equals the intended traversal order (launcher → new-Claude → new-admin → dropdown
   control → items → item actions), asserted as the literal markup order in `index.html`.
2. **Roles and states**: the dropdown carries `role="menu"` and toggles ONLY `aria-expanded` (on
   the control) and `aria-hidden` (on the panel); items carry `role="menuitem"`; the admin control
   carries `aria-disabled="true"` whenever it is in a disabled state (never the `disabled`
   property, so it stays focusable) and a `title` carrying the state copy verbatim; the reason note
   is visible text (the accessible authority, design §6).
3. **The fence** (design §7.6): the setAttribute allowlist covers the a2p attributes and the
   no-`innerHTML` rule still holds across all three picker files.

Browser-level (chromedriver; scripted world per `test_c1a1_browser.py`; free port; skip only when
chromedriver/chromium are absent — as everywhere in this repo):

4. **Full keyboard walk, closed bar**: Tab from the launcher control reaches new-Claude →
   new-admin → dropdown control, in order, and each Enter/Space fires its action (launcher opens;
   Claude's flow opens — assert via its existing seam; the hand-off asserted with a click-capture
   that `preventDefault()`s and records the href). Arrow keys on a focused disabled control do
   nothing and move nothing.
5. **Open by keyboard, walk the menu**: Enter on the dropdown control opens it and focus stays on
   the control (a2h law); ArrowDown moves to the first enabled item, ArrowUp from the first wraps
   to the last, down past the last wraps to the first; disabled items are skipped by the arrows and
   Enter on them fires nothing; Escape closes and refocuses the control, with `aria-expanded` false
   after the close (the a2h law re-asserted here so a2p's own fence owns it).
6. **Stop is keyboard-reachable**: Enter on the admin row's Stop fires exactly one
   `POST /api/launcher/stop` with body `{"target":"admin","project":...}` (assert the captured
   body), and the row refreshes from the following list answer.
7. **`aria-expanded` on pointer paths**: click-open → true; click-away → false (the law
   `test_ui.py` pins by source is *observed* here).
8. **No focus trap**: while the dropdown is open, Tab from the last item leaves the picker to the
   document (menu semantics, not dialog): assert focus lands outside the bar.

Each test is one behaviour, named for it, with the assertion message quoting the element id.

### The shots suite — `hub/tests/test_a2p_shots_browser.py`

- The populated fixture per design §8: launcher options present; one running Claude session with a
  real title and one stopped; admin project `website` running (`state:"running"`, deadline inside
  the window, member `dev`) plus one crashed admin row; `project_admin` on; `admin_origin`
  `https://admin.example.com`. Status/options/hosts answers scripted;
  `POST /api/launcher/stop` answered `{ok:true}` (the open shots must not depend on real daemon
  behaviour).
- Explicit waits: a poll-until helper (≤2 s deadline) on each element the shot must contain — the
  dropdown populated, the admin row's state text, the Stop button; no fixed sleeps as the sync
  point.
- Theme: toggle `document.documentElement.classList` `dark` (the app's own mechanism, as
  `test_h3_browser.py`'s `_set_theme` does); wait one `requestAnimationFrame` after the toggle
  before the capture so the repaint is in.
- For each (viewport 390×800 and 1440×900) × (light, dark): load the full page, wait settled,
  capture **closed**; open the dropdown, wait for the populated panel, capture **open**. The eight,
  at design §8's exact names.
- **Shots directory**: `os.path.join(os.environ.get("DELEGATE_EVIDENCE_DIR", "/tmp"), "a2p-shots")`,
  created by the test; the name template lives in the test as a constant (the same one the verify
  greps — file list and test cannot drift). Each PNG is written via the CDP `Page.captureScreenshot`
  mechanism `test_h2_browser.py`'s `PageSession.screenshot` uses — but the test resolves its own
  directory instead of depending on that method's return (it is None without the env var): write
  the bytes yourself, assert the file exists and is non-empty, print one `SHOT <path>` line per PNG.
- **The test FAILS (not skips) when fewer than eight files exist at the end** — including when the
  browser is missing: browser-missing where shots were demanded is the same "not available ≠
  passing" rule the daemon suite uses. (Where chromium is absent the verify's own count check
  fails too — belt and braces, design §8.)
- A ninth "state sheet" is explicitly NOT produced (out of scope; the closed/open pairs carry the
  review).

## Behaviour and edge cases to cover

- Disabled-but-reachable: test 4 asserts the focused disabled control swallows Enter/Space/Arrow
  with no state change anywhere (`aria-expanded` untouched, no navigation, no request).
- The shots test asserts, before each open capture, that the visible copy matches the design §5
  strings for the admin row and the session rows — a shot can never show drifted copy.
- The open shots must show the dropdown (not a full-page menu): assert the panel's bounding box
  starts below the bar and `document.documentElement.scrollWidth <= innerWidth` checked immediately
  before every 390 capture (the no-horizontal-scroll rule; fail, don't warn).
- Determinism by construction: the eight names are a constant in the test, so two runs produce the
  same list.

## Acceptance

Verify — exactly the chain's step-3 command (hard, last step: full gate, the eight-PNG count,
scope guard; a missing browser or a skipped shot fails the `grep -qx 8` / `MISSING OR FAILED`
clauses — there is no path to green without the artifacts):

```
set -o pipefail; V="${DELEGATE_EVIDENCE_DIR:-/tmp}/verify-a2p3.log"; SHOTS="${DELEGATE_EVIDENCE_DIR:-/tmp}/a2p-shots"; rm -rf "$SHOTS"; python3 tools/run_tests.py > "$V" 2>&1 || { F=$(grep -E '^FAIL +' "$V" | awk '{print $2}' | tr '\n' ' '); [ -n "$F" ] || { tail -80 "$V"; exit 1; }; echo "re-running once (load flakes): $F"; python3 tools/run_tests.py -j 2 $F > "$V.rerun" 2>&1 || { tail -80 "$V.rerun"; exit 1; }; for m in $F; do sed -i -E "s/^FAIL( +$m )/ok\1/" "$V"; done; }; for m in hub.tests.test_a2p_a11y hub.tests.test_a2p_shots_browser hub.tests.test_ui hub.tests.test_sessions_ui hub.tests.test_c1a1_browser hub.tests.test_h3_browser hub.tests.test_anonymity hub.tests.test_image_imports; do grep -qE "^ok +$m " "$V" || { echo "MISSING OR FAILED $m"; grep -E 'FAIL|not ok' "$V" | head -10; exit 1; }; done; ! grep -qE '^FAIL +|^not ok' "$V" || exit 1; ls "$SHOTS" | grep -cE '^(390x800|1440x900)-(light|dark)-(closed|open)[.]png$' | grep -qx 8 || { echo "ACCEPTANCE PNGs: expected 8, got $(ls "$SHOTS" 2>/dev/null | wc -l)"; exit 1; }; git diff --name-only delegate/a2p-2-admin-handoff | grep -qvE '^(hub/static/(index[.]html|app[.]css)|hub/static/views/adminsession[.]js|hub/tests/(test_a2p_a11y|test_a2p_shots_browser|test_ui)[.]py)$' && { echo 'a2p-3 touched files outside its scope'; exit 1; }; grep -E '^run_tests:' "$V"; ls -l "$SHOTS"
```

- [ ] every §Contract browser test exists and passes;
- [ ] eight PNGs at the exact names, each non-empty; the light and dark pairs differ in byte size
      by more than noise (you compared the sizes and quoted them);
- [ ] the 390 closed/open shots contain the whole bar, no horizontal scroll;
- [ ] `python3 tools/run_tests.py` exit 0, both suites;
- [ ] the diff contains no non-a11y/visual product change.

## Out of scope for this step

Behavioural change beyond a forced a11y/visual fix; a state-sheet composite; any role/semantics
redesign — if the audit finds the contract itself unworkable (for example menuitem semantics
fighting the a2h focus law), stop and report DESIGN PROBLEM rather than improvise.

## Host traps

- **The a2h law stays true under your probes**: if your keyboard test breaks it, the existing
  `test_h3_browser.py` bites immediately — run it while developing, not only at the end.
- **Screenshots race the page**: any flake shows as a blank or half-populated PNG. The poll-until
  helper is mandatory (h2/h3 show the pattern); fixed sleeps are the classic way to produce a green
  test whose PNGs lie.
- **Theme repaint lag**: toggling `.dark` and capturing in the same frame yields a half-themed
  shot; wait the frame.
- **A capture of an auto-closed dropdown**: the Tab probes in the a11y suite click around — in the
  shots suite, capture immediately after the open-and-wait and click nothing near the capture.
- **Chromium flags**: the h2/h3 flag set (`--no-sandbox` etc.) is the working one — copy it.
- **`PageSession.screenshot()` returns None without the env var** — write the file yourself from
  the CDP response, as the contract says.
- **scrollWidth at 390** changes if a scrollbar appears mid-poll — check immediately before the
  capture, not at page load.
